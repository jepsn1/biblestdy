# No toasts: an inline notice next to the action (#257)

**Date:** 2026-11-21. **Panel:** Sofie, Mads, Jonas, Birthe, Freja, Elias (the UI chrome / a11y / overlays row). There was one findings round on a builder's proposal with a lean, then one ok/objection round on a decisions draft. The evidence was before-shots of the old toasts plus shots of today's surfaces (reader end, open note, Notes page, search sheet, settings) on phone and desktop. The panel also read the code (`lib/notify.ts`, `marks-load-error.tsx`, `page-foot.tsx`, `paginated-chapter.tsx`, `note-panel.tsx`, `command-palette.tsx`).

**Owner (binding):** "i want 0 toasts on mobile no matter what. it needs other UI closer to the action anyway and something that doesn't obstruct the view". Phones get zero toasts, including errors and Undo. If the inline pattern works on desktop too, one pattern everywhere is preferred.

**Step 1 (already in this PR):** the routine success/info toasts are gone: Highlighted, Copied, translation switched, theme/style/colour filter changed, draft restored, tour later, and the eraser-over-a-link hint. Screen readers still hear them through a polite live region (`lib/announce.ts`) with no visible chrome.

## Decisions (6/6 unless noted)

- **D1: one inline notice component everywhere.** Sonner (the toast library) is removed on desktop too. Jonas's correction: Sonner was already lazy-loaded, so removing it saves its 9.6 KB gz post-paint chunk but nothing on first paint. The notice store and component add about 1–2 KB gz to first paint.
- **D2: look.**
  - Uses `text-control`, so it follows the text size. The message is muted; an error colours only its message in destructive red (≥4.5:1). Undo/Retry is an underlined word button in the foreground colour, the "Couldn't load your marks" look. Birthe: big and dark, not grey.
  - Touch targets reach 44px through padding, so the line doesn't grow.
  - × appears only on errors, labelled "Close" / "Luk" (Mads: Undo expires on its own anyway).
  - Danish: "Fortryd", "Prøv igen". No icons and no fill (Freja dropped her icon request in round 2). A 150 ms fade, none with reduced motion.
- **D3: one notice per place.** A newer one replaces it. Same-kind removals merge and give the count: "3 highlights removed · Undo" restores all three, and the timer restarts (Elias, Jonas). The text always says what Undo will restore (Sofie). Undo outranks info: a "Copied" never replaces a visible Undo (Jonas).
- **D4: in place.**
  - Tag chip → plain muted "Removed · Undo" at the same height, with no dashed border. The width reflows instantly with no animation, and only the final collapse fades (Mads).
  - Verses row → "John 3:16 removed · Undo", no strike-through (Mads: a line through a reference reads like an editor's mark).
  - Notes-page row → "Note deleted · Undo".
  - "Ryd" → "Recent cleared · Undo" until the sheet closes (Sofie: one lifetime).
  - Focus: if focus was on the removed thing's ×, it lands on the in-place Undo. When that goes, focus moves to the next chip or row, otherwise to "+ add" (Jonas, Elias).
- **D5: desktop reader.** The notice takes the support line's place ("Buy me a coffee · Share") under the running foot: same line box, constant foot height, and it never pushes the columns, so no repagination (Mads F1, Jonas F2).
  - It is clamped to one line, with the full text in the live region (Jonas).
  - It lives in one turn-still layer shared with "Couldn't load your marks", so it never slides with a page turn.
  - No second home in the eraser pill. Elias and Birthe wanted one in round 1 and dropped it in round 2 once Ctrl+Z existed.
- **D6: keyboard.** Ctrl/Cmd+Z runs the visible Undo when focus isn't in a text field. The note editor's own undo wins, and key repeats are ignored. On desktop the notice reads "Undo (Ctrl+Z)", with the hint muted and outside the underline (Mads). It is listed in the shortcuts help. Esc never dismisses a notice (Elias).
- **D7: routing, never silent.**
  - A notice whose own place is gone falls back to the page's place, then to the note's row. Two examples: Settings closed before its save failed; the phone bar hidden while a note drawer is open (Jonas F3).
  - With nothing mounted, the notice waits until a place mounts. The Notes page has its own line.
  - Settings errors say what's in effect: "Text size not saved, still 100% · Retry" (Sofie).
- **D8: copy limit** is ≤40 characters so it fits the phone row: "Copy limit: 100 verses at a time" / "Højst 100 vers ad gangen" (Mads F4). "Undo failed" goes to the same place as its Undo.

## Conflicts, settled in round 2 (all 6/6)

- **C1, phone reader: a notice row grows inside the bottom bar, above the unchanged ‹ Find › buttons** (b). Round 1 was 3–3 against swapping the bar's content.
  - Against the swap: Freja, Birthe and Sofie said thumb habit lands on Undo where "Chapter 4 ›" was. Jonas showed that swapping unmounts a focused button, takes chapter nav and Find away for 10 s, and that the bar is inert and invisible while a note drawer is open.
  - The row uses the bar's own surface with a 1px hairline. Its height snaps and only the text fades (Mads).
  - The text viewport gets about 36–44px shorter from the bottom. The column width stays, so nothing rewraps and the scroll position stays. Nothing covers the text and the arrows never move.
- **C2, Undo on touch lasts 20 s** (desktop 10 s, paused while hovered or focused). Touch has nothing to pause it. "Touch" comes from the input that did the removal, not from a media query, because hybrid laptops misreport (Jonas).
- **C3, page turns and chapter changes keep the notice** until its time is up. The chrome never moves; only the text does (Elias: ←/→ would otherwise kill every Undo). The Undo's closure already knows its chapter.
- **C4, the draft prompt is a row at the top of the note body**, shown only when the note opens (Jonas: the footer is hidden while the phone drawer is peeked).
  - Wording: "Newer unsaved text from 14:32 on this device · Use newer · Keep current" / "Nyere ikke-gemt tekst fra 14.32 på denne enhed · Brug nyere · Behold nuværende". Freja: "Keep this" was unclear. Jonas: "this device", because we can't tell iPad from phone without sniffing.
  - The buttons are in the tab order before the editor (Elias). If the prompt is ignored, it is offered again next time and nothing is lost.
- **C5, visible copy confirmation in place.**
  - The Copy control reads "Copied ✓" for about 1.5 s at a fixed width, then the menu closes; any new tap closes it at once (Jonas).
  - The keyboard "c" shows "Copied John 3:5" in the desktop notice place for 3 s, never over a visible Undo.
  - The screen-reader announcement stays.
  - Freja and Birthe raised this as major: Copy had shown nothing since step 1.
